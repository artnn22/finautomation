# Опекс

«Опекс» обрабатывает список эмитентов, рассчитывает финансовые показатели и собирает локальный HTML-отчёт. В отчёте можно перейти из скринера в карточку эмитента, раскрыть формулу и проверить исходные значения, посмотреть сигнал P/E, сценарный пересчёт и прогноз выручки.

## Быстрый запуск

Локальный интерфейс аналитика в Linux и macOS:

```sh
bash run-demo.sh --web
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Форма принимает тикеры текстом или CSV, отчётность и котировки, фильтры, сценарий и минимум истории прогноза. Доступны учебный, локальный и онлайн-режимы, история запусков и светлая или тёмная тема. Сводка и первые восемь строк скринера загружаются отдельно. Полный HTML открывается при выборе соответствующей вкладки. Входные CSV передаются в локальный процесс, общий размер одного запроса ограничен 12 МБ. Результаты сохраняются в `runs/web/`. Другой порт можно задать через `--port`.

### Пакетный учебный запуск

В Linux и macOS выполните из корня репозитория:

```sh
bash run-demo.sh
```

Скрипт использует готовое окружение `.venv` для текущей версии и обновляет его при смене версии. Для установки с нуля нужны Python 3 с модулями `venv` и `pip` и доступ к сети. Если команда `uv` недоступна, скрипт установит её в `.venv-tools` от имени пользователя. Системных изменений и `sudo` запуск не требует.

В последней строке вывода будет путь к новой папке. Откройте в ней `report.html`. В учебном наборе восемь синтетических эмитентов, семь из них проходят отбор. Для **DEMO01** ожидается сигнал расхождения P/E на 24,46%. Сценарий из примера увеличивает выручку на 10%, снижает маржу EBITDA на 2 п. п. и увеличивает долг на 100 единиц валюты.

## Автоматическая загрузка отчётности и котировок

После первого запуска скрипта выполните команду для пяти реальных инструментов:

```sh
./.venv/bin/python -m finautomation.main run \
  --tickers examples/online/tickers.csv --online-financials --online \
  --period-dates examples/online/period_dates.csv \
  --config examples/verification/config.yaml --out runs/online
```

`--online-financials` загружает годовые и квартальные строки Yahoo Finance. В CSV сохраняются имена исходных полей, даты, валюты и полученные числовые значения. Шаг `--online` отдельно загружает дневные цены. Оба входа сохраняются в `inputs/`. Настройки фильтра и сценария одинаково работают с локальными и загруженными данными.

Список может содержать обе площадки. Для MOEX подайте отчётность в CSV через `--financials`. При сочетании `--financials` и `--online-financials` локальные строки имеют приоритет для всей пары «площадка + тикер». Котировки по каждой бумаге берутся с указанной площадки. Раздел ЦКИ с отчётностью Мосбиржи требует отдельного доступа. [Центр корпоративной информации Мосбиржи](https://www.moex.com/tsentr-korporativnoj-informatsii), [справка о данных Yahoo Finance](https://help.yahoo.com/kb/finance/risk-overview-sln2303.html).

По умолчанию используется дата периода из Yahoo Finance. Если источник округлил дату к концу месяца, например для календаря Apple, передайте точную дату из отчёта через `--period-dates`. Столбцы смотрите в [примере](examples/online/period_dates.csv). Обе даты сохраняются в следе расчёта. Доступная история зависит от эмитента. Пропуск периода прерывает ряд для прогноза. [Отчётность Apple](https://investor.apple.com/investor-relations/default.aspx).

## Контрольный список реальных бумаг

В `examples/verification/` лежат список **AAPL, MSFT, SBER**, подготовленные данные из публичной отчётности и снимок 41 фактически использованной котировки. Снимок позволяет повторить проверку без сети. Пути к отчётам эмитентов и даты получения записаны в CSV.

```sh
./.venv/bin/python -m finautomation.main run \
  --tickers examples/verification/tickers.csv \
  --financials examples/verification/financials.csv \
  --quotes examples/verification/quotes.csv \
  --config examples/verification/config.yaml --out runs/verification
```

Для прямого запроса котировок замените `--quotes examples/verification/quotes.csv` на `--online`. Отчётность в этой команде берётся из подготовленного CSV. [Документация MOEX ISS](https://www.moex.com/a2193).

## Входные данные

| Файл | Формат |
| --- | --- |
| `tickers.csv` | `ticker,market`, где `market` равен `moex` или `yahoo`. |
| `financials.csv` | Ключ `source,ticker,currency,period_type,period_end`. Финансовые поля перечислены в [учебном CSV](examples/demo/financials.csv). `Q` означает квартал, `FY` — финансовый год. |
| `quotes.csv` | `source,ticker,currency,date,close`. Для связи с отчётностью должны совпадать площадка, тикер и валюта. |
| `config.yaml` | Список фильтров `field/op/value`, сценарий `r/m/delta_d`, минимальная история `forecast.min_train_periods`, настройки онлайн-котировок. См. [пример](examples/demo/config.yaml). |

CSV принимаются в UTF-8 с BOM или без него, с запятой или точкой с запятой между столбцами. Даты имеют формат `YYYY-MM-DD`, дроби записываются через точку. Пустые и некорректные числа дают пропуски с пояснениями. Нулевую корректировку EBITDA передавайте явно. Налог указывается со знаком расхода (плюс) или дохода (минус).

- `amount_scale` переводит финансовые суммы в единицы валюты, `shares_scale` переводит число акций в штуки, `price_scale` переводит цену в единицы валюты за акцию. По умолчанию каждый множитель равен 1. Скринер показывает суммы в единицах валюты, указанной в строке. Укажите документ или URL в `source_ref`, дату получения в `retrieved_at` и исходное название показателя в необязательном столбце вроде `revenue_source_field`.
- Готовые квартальные потоки передавайте как `Q` с пустым `flow_basis` или `flow_basis=period`. Для накопленных потоков используйте `flow_basis=ytd`, `fiscal_year=YYYY` и `fiscal_quarter=1…4`. Метка `fiscal_year` должна совпадать у кварталов и `FY`. По умолчанию для `FY` используется год даты окончания. Балансовые величины берутся на конец соответствующего периода. Если записи Q4 нет, она выводится из FY и YTD3 того же финансового года при наличии обоих периодов. Используйте сопоставимый стандарт отчётности и один вид потоков на строку.
- Для MOEX по умолчанию берётся режим `TQBR`. Другой режим для тикера можно задать в `quotes.moex_boards`. Для Yahoo используется дневной `close`. Учитывайте, что исторический ряд Yahoo может быть приведён с учётом дроблений. Число акций и цена для капитализации должны быть на одной базе.
- Скринер берёт последнюю строку каждой частоты по инструменту. Все фильтры применяются к одной строке. Например, фильтр по `pe_fy` применяется к строке FY, где есть годовой P/E. Значения долей и изменения маржи задаются десятичными дробями. `delta_d` задаётся в единицах валюты отчётности каждой строки.

## Расчёты и результаты

- Показатели включают прибыльность, EBITDA и Adjusted EBITDA, налоги, ликвидность, долг, денежные потоки и рыночные мультипликаторы. Для цены берётся последнее закрытие на отчётную дату или раньше. Сигнал P/E сравнивает последний завершённый FY и четыре последовательных квартала с одной капитализацией на конец последнего квартала. Порог сигнала строго больше 20%.
- Сценарий использует выручку, маржу EBITDA и долг из базовой строки. Изменение OCF равно изменению EBITDA. Налог, цена, число акций, денежные средства и CapEx фиксированы в рамках модели.
- Для прогноза выбирается вариант линейной регрессии по прошлым ошибкам конкретного ряда. Используются обычный, недавний и квартальный сезонный тренды. В отчёте и `metrics.json` видны оценки выбранной модели, прежнего линейного тренда и Naive на одних и тех же точках отдельно для Q и FY. [Принцип работы модели и контрольный пример](docs/Прогноз%20выручки.md).
- Каждый запуск создаёт отдельную папку. В ней есть `report.html`, `parse_log.csv`, `issuer_metrics.csv`, `formula_trace.csv`, `screener.csv`, `alerts.csv`, `scenario.csv`, `forecast_next_period.csv` и `metrics.json`. В выходных CSV разделитель — точка с запятой. В `metrics.json` MAPE и охват записываются долями.
- Папка `inputs/` хранит использованные CSV и YAML, включая отчётность и цены, полученные онлайн. Для повторения подайте эти снимки через `--financials` и `--quotes`. При смешанном запуске добавьте отдельный `--financials` для файла `financials_yahoo.csv`. Исправленные даты уже записаны в снимок отчётности. Для резервной копии скопируйте всю папку запуска на выделенный накопитель.
- Коды завершения `0`, `1` и `2` означают соответственно наличие обработанной отчётности, отсутствие пригодных отчётных строк и ошибку запуска или формата. Доля обработки считается среди уникальных допустимых пар «площадка + тикер» по наличию отчётности и хотя бы одной соответствующей котировки. При недоступном источнике расчёты по самой отчётности продолжаются. Проверку критериев смотрите в `metrics.json`.
