# Опекс

Пакетный анализ эмитентов на Python 3.13. На входе список бумаг, подготовленная отчётность и котировки из CSV либо с биржевого источника. На выходе локальный HTML-отчёт, показатели, следы расчёта, скринер, сценарий и прогноз выручки.

## Учебный запуск

Установите `uv`. Из корня проекта выполните:

```sh
uv sync --locked
uv run --locked finautomation run \
  --tickers examples/demo/tickers.csv \
  --financials examples/demo/financials.csv \
  --quotes examples/demo/quotes.csv \
  --config examples/demo/config.yaml \
  --synthetic-demo --out runs/demo
```

Команда напечатает путь к новой папке. Откройте в ней `report.html`. Пример включает восемь фиктивных эмитентов и работает без доступа к источникам котировок. Замените `tickers.csv` на `new_tickers.csv`, чтобы прогнать ещё три фиктивные бумаги с подготовленными данными. Для нового списка можно указать `--out runs/new-list`.

## Свои данные и онлайн-котировки

Подготовьте `tickers.csv` и `financials.csv` по заголовкам из [учебного набора](examples/demo/). Для реальных российских компаний перенесите нужные строки из опубликованных отчётов эмитента. Сервис автоматически получает только котировки.

```sh
uv run --locked finautomation run \
  --tickers tickers.csv --financials financials.csv \
  --online --config examples/demo/config.yaml --out runs/live
```

Для `market=moex` загружается дневная история акций MOEX ISS. По умолчанию используется режим `TQBR`. Для отдельных бумаг его можно задать в `quotes.moex_boards`, например `{SBER: TQBR}`. Для `market=yahoo` загружается дневной `Close` из Chart API Yahoo Finance. Используется поле `close` без поправки на дивиденды. Yahoo может представлять историческую цену с учётом дробления акций. Для капитализации число акций должно быть на той же базе. Если нужна историческая цена и число акций на исходную дату без пересчёта, передайте согласованные значения через CSV.

Онлайн-запуск сохраняет фактически загруженные цены в `inputs/quotes.csv`. Для повторного прогона используйте снимки `inputs/tickers.csv`, `inputs/financials.csv`, `inputs/config.yaml` и укажите `--quotes inputs/quotes.csv` с путями относительно папки первого запуска. Если источник недоступен или вернул цены в другой валюте, расчёты по отчётности продолжаются, а зависимые от цены показатели остаются пустыми.

### Формат файлов

- `tickers.csv` содержит `ticker,market`. Используйте тикер выбранного источника. Регистр букв в тикере приводится к верхнему.
- `financials.csv` содержит `source,ticker,currency,period_type,period_end` и финансовые поля из заголовка примера. `Q` означает отдельный квартал, `FY` означает финансовый год. По одному эмитенту используйте сопоставимые данные одного стандарта отчётности и одного масштаба. Приведите суммы к единицам указанной валюты и укажите число акций в штуках. Для квартальных потоков из накопительных отчётов используйте `Q1 = YTD1`, `Q2 = YTD2 − YTD1`, `Q3 = YTD3 − YTD2`, `Q4 = FY − YTD3`. При отсутствии соседнего значения оставьте поле пустым. Балансовые остатки берите на конец периода. `income_tax_expense` положителен для расхода и отрицателен для дохода. Пустой `ebitda_adjustments` обозначает отсутствие данных, поэтому нулевую корректировку указывайте явно.
- `quotes.csv` содержит `source,ticker,currency,date,close`. Ключ инструмента в обоих файлах одинаковый, включая валюту. Финансовые поля и котировки могут дополнительно содержать `source_ref` с названием документа или ссылкой и `retrieved_at` с датой получения. Для реальных данных заполните оба поля.
- Даты задаются в формате `YYYY-MM-DD`, дроби с десятичной точкой, кодировка UTF-8 с BOM или без него. Разделитель столбцов — точка с запятой или запятая. В выходных CSV используется точка с запятой.

В YAML задаются фильтры `field/op/value`, сценарий `r/m/delta_d` и минимальная длина непрерывного ряда для обучения. Доли и изменение маржи задаются десятичными дробями. На экране отбора рассматривается последняя запись каждой частоты по инструменту. Например, фильтр по `pe_fy` требует годовой строки с доступным значением.

## Результаты и проверка

- `report.html` открывается локально. В карточке раскройте период и формулу, чтобы увидеть исходные значения и даты.
- `issuer_metrics.csv` и `formula_trace.csv` содержат показатели и следы расчёта. `screener.csv`, `alerts.csv`, `scenario.csv` и `forecast_next_period.csv` содержат результаты соответствующих этапов.
- `parse_log.csv` описывает ошибки и итог по каждой запрошенной бумаге. В `metrics.json` доля обработки рассчитывается по уникальным корректным тикерам с отчётностью и хотя бы одной подходящей ценой. MAPE записывается долей, например `0.2` для 20%. Коды завершения — `0` при наличии обработанной отчётности, `1` если нет ни одной обработанной строки, `2` при ошибке формата файла или конфигурации.
- Расчёты следуют [обновлённому ТЗ](docs/ТЗ%20ОПЕКС%20обновленное.txt). Для сигнала P/E используется общая капитализация на конец последнего квартала. Модель выручки — линейный тренд по последовательным кварталам или годам. Контрольный период всегда следует за обучающей историей. Учебный прогон проверяет работу алгоритма. Качество прогноза и охват реальных тикеров оцениваются на отдельном согласованном наборе.

```sh
uv run --locked python -m unittest discover -s tests -v
```
