# Техническое описание «Опекса»

Рабочий справочник по версии 0.3.0 для разработки и тестирования. Основание проекта — принятые ТЗ и пояснительная записка. Обязательные формулы и критерии приёмки берутся из этих документов.

## Назначение и границы

«Опекс» пакетно обрабатывает данные публичных эмитентов. На входе список бумаг, финансовая отчётность, дневные цены и параметры прогона. На выходе локальный HTML-отчёт с результатами отбора, карточками эмитентов и следами расчёта, а также CSV и JSON. Система работает на Python 3.13. Для прогноза используется scikit-learn. [Запуск и примеры](../README.md).

ТЗ ограничивает источники MOEX ISS, Yahoo Finance и локальными CSV. Предмет прогноза — выручка на один отчётный период. Конвертация валют, преобразование стандартов отчётности, прогноз цены и исполнение сделок находятся за пределами проекта.

## Входы и режимы

| Вход | Ключ и назначение |
| --- | --- |
| `tickers.csv` | `ticker,market`. Допустимые источники `moex` и `yahoo`. |
| Финансовая отчётность | `source,ticker,currency,period_type,period_end`. `Q` — квартал, `FY` — финансовый год. |
| Котировки | `source,ticker,currency,date,close`. `close` — дневная цена закрытия. |
| `config.yaml` | Условия скринера, параметры сценария, минимум истории для обучения, таймаут и режимы торгов MOEX. |
| `--period-dates` | Поправки к датам Yahoo. Ключ `ticker,currency,period_type,source_period_end`, значение `period_end`. Обе даты остаются в снимке и следе расчёта. |

- **Локальный запуск.** Отчётность и цены читаются из подготовленных CSV. Можно передать несколько файлов отчётности.
- **Онлайн-запуск.** `--online` загружает дневные цены с источника каждой бумаги. `--online-financials` отдельно запрашивает годовые и квартальные показатели Yahoo Finance.
- **Смешанный запуск.** Локальная отчётность имеет приоритет для всей пары `source,ticker`. По другим запрошенным бумагам Yahoo работает онлайн. Для бумаг MOEX финансовая отчётность подаётся как CSV, а рыночные цены можно получить из MOEX ISS.

Входные файлы и скачанные данные сохраняются в `inputs/`. Повтор из снимков запускается с локальными входами. В смешанном режиме для второго снимка используется ещё один `--financials`. [Описание команд](../README.md).

## Поток обработки

| Этап | Правило | Модуль |
| --- | --- | --- |
| Сбор | Считываются запрошенные пары «источник + тикер». Сбой источника или отдельной бумаги фиксируется в журнале, пакет продолжается. | [financials.py](../src/finautomation/financials.py), [quotes.py](../src/finautomation/quotes.py) |
| Нормализация | `amount_scale` переводит суммы в единицы валюты, `shares_scale` — число акций в штуки, `price_scale` — цену в единицы валюты за акцию. Исходное поле, число, масштаб, источник и дата доступны в следе. | [inputs.py](../src/finautomation/inputs.py) |
| Периоды | Потоки Q1 берутся из YTD1, Q2 и Q3 вычисляются разностью соседних накоплений, Q4 — разностью FY и YTD3 одного финансового года. Остатки берутся на конец периода. Для числового расчёта нужны оба значения соответствующей разности. | [inputs.py](../src/finautomation/inputs.py), [periods.py](../src/finautomation/periods.py) |
| Связь с рынком | Связь идёт по `source,ticker,currency`. Берётся последнее доступное закрытие на дату отчёта или раньше. Для доходностей используются такие же отсечки за 1, 3 и 12 месяцев. | [metrics.py](../src/finautomation/metrics.py) |
| Расчёт и выгрузка | Формируются показатели, отбор, сценарий, прогноз, журнал и HTML. В карточке раскрываются формулы, исходные значения и причины пропусков. | [main.py](../src/finautomation/main.py), [report.py](../src/finautomation/report.py) |
| Локальный веб-интерфейс | Форма передаёт параметры тому же расчёту. Сводка возвращается в JSON, полный HTML загружается по запросу. Сервер слушает только loopback. | [web.py](../src/finautomation/web.py), [интерфейс](../src/finautomation/web_static/index.html) |

Точные повторы учитываются один раз. Конфликтующие записи одного ключа исключаются и попадают в журнал. Для пропусков, некорректных чисел, неприменимой формулы и нулевого знаменателя значение остаётся пустым, а причина доступна в следе.

## Ключевые правила расчёта

- **EBITDA и налог.** EBITDA равна операционной прибыли плюс амортизация. Adjusted EBITDA требует явной корректировки, включая допустимый ноль. Эффективная ставка налога равна расходу по налогу, делённому на прибыль до налога, если прибыль положительна.
- **P/E.** P/E FY делит капитализацию на конец FY на чистую прибыль этого года. P/E TTM использует капитализацию на конец квартала и прибыль за четыре последовательных квартала. Для сигнала обе оценки пересчитываются с одной капитализацией на конец последнего квартала. Абсолютная разность этих оценок делится на `max(abs(P/E TTM), 0.000001)`. Сигнал появляется при значении строго больше 20%.
- **Скринер.** Для каждого инструмента отдельно проверяется последняя строка Q и FY. Строка проходит, если удовлетворяет всем активным фильтрам. Пустое значение не проходит условие.
- **Сценарий.** Меняются выручка, маржа EBITDA и долг. Изменение операционного денежного потока равно изменению EBITDA. Цена, число акций, денежные средства и капитальные затраты фиксированы. Базовая отчётность сохраняется.
- **Прогноз.** Система выбирает вариант линейной регрессии отдельно для каждого непрерывного ряда Q и FY. Историческая проверка сравнивает выбранный вариант, обычный линейный тренд и Naive на одинаковых точках с положительным фактом. При недостатке истории или допустимых точек у оценки статус `not_evaluable`. [Принцип работы](Прогноз%20выручки.md).

## Что проверяется при приёмке

| Критерий ТЗ | Как проверить в продукте |
| --- | --- |
| Корректны все применимые формулы, пропуски объяснены | Сверить ручные контрольные значения с `issuer_metrics.csv` и `formula_trace.csv`. |
| Учебный набор от восьми эмитентов даёт непустой отбор | Запустить `run-demo.sh`, сверить `screener.csv`. |
| Охват нового корректного списка не менее 70% | В `metrics.json` сверить долю уникальных запрошенных пар с пригодной отчётностью и хотя бы одной подходящей ценой. |
| Виден расчёт EBITDA, налоговые значения совпадают с отчётностью | Раскрыть формулы в карточке и проверить операционную прибыль, амортизацию, прибыль до налога и налог из источника. |
| MAPE модели не выше 20% или меньше MAPE Naive | Сверить допустимые точки в `forecast_next_period.csv`, оценки и статус в `metrics.json`. |
| Цена, валюты, обе методики P/E и сценарий проверяемы | Проверить отсечку цены, порог сигнала и сравнение исходных и сценарных значений. |
| Пакет обрабатывает ошибку отдельной бумаги и выпускает результат за один запуск | Включить ошибочную строку вместе с корректными и сверить `parse_log.csv`, HTML и комплект выгрузок. |

Фактические результаты, контрольные примеры и ограничения выборок записаны в [методике проверки](Проверка.md).

## Ограничения текущей реализации

- История онлайн-отчётности зависит от данных поставщика. При округлении дат можно передать точный календарь эмитента. Дата будущего периода оценивается сдвигом на 3 или 12 месяцев.
- Для CSV с накоплениями одна строка задаёт один вид потоков. Подготовка строк из разных стандартов отчётности и выбор сопоставимых статей выполняются при составлении входного файла.
- Реальные проверки включают 24 квартальные точки Microsoft, четыре квартальные точки онлайн-списка и две годовые точки контрольного CSV. Для приёмочного прогона нужны отдельные согласованные входы и параметры.
